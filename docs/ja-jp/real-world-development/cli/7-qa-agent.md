これまでに `quality-checks` スキルで自動チェックを実行し、Playwright MCP でブラウザー上のフィルター操作を確認しました。今度は、これらの機能を明確な QA プロセスを持つカスタムエージェントにまとめます。

このレッスンでは、次のことを行います。

- カスタムエージェントが指示、スキル、MCP ツールと連携する方法を確認します。
- 再利用可能な品質保証プロファイルを作成して調べます。
- QA エージェントを選択し、フィルター issue に照らした結果をレビューします。

## シナリオ

Tailspin Toys では、プルリクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テスト範囲、ブラウザー上の動作を一貫して確認したいと考えています。カスタムエージェントを使うと QA プロセスをまとめ、再利用できるレポートを作成できます。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する Copilot の特化バージョンです。プロファイルにはエージェントの目的、指示、利用可能なツールを記述します。このワークショップでは `.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまで使ったカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を示し、`quality-checks` スキルは繰り返し実行するチェックをまとめます。Playwright MCP はブラウザーツールを提供します。QA プロファイルは、要件の評価と結果の報告にこれらの機能を使う方法を Copilot に伝えます。既存の機能を置き換えるものでも、別の会話を必要とするものでもありません。

## QA プロファイルを作成する

機能の PR を開く前に、再利用できる QA プロファイルを Copilot に作成してもらいます。プロファイルには、QA が行うチェックと守るべき境界の両方を定義します。

1. Codespace に戻り、フィルターの会話が Interactive モードであることを確認します。
2. 既定のエージェントに新しいカスタムエージェントを作成するよう依頼します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタムエージェントを作成してください。機能と issue および合意済みの要件を照合し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP を使って動作を検証し、テスト範囲が不足している場合はテストを追加してください。

   各要件を、根拠を添えて pass、fail、blocked のいずれかで報告してください。実装コードを変更する前に確認を求め、変更をコミットしたりプルリクエストを開いたりしてはいけません。

   まずプロファイルだけを作成し、レビューできるようにしてください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、意図した QA の手順と境界がプロファイルに含まれていることを確認します。これにより、検証だけを行いたいときに、Copilot が不完全または広範すぎる指示で機能を変更することを防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. frontmatter を読みます。`description` は必須です。`name` は省略できますが、含めるとエージェント名が分かりやすくなります。
3. プロファイルの指示を読み、QA が要件から始め、リポジトリの指示に従い、`quality-checks` スキルを実行して Playwright MCP を使うことを確認します。
4. QA が根拠を報告し、実装コードの変更前に確認を求め、変更をコミットせずプルリクエストも開かないことを確認します。
5. これらの責務や境界が不足している場合は、続行する前に既定のエージェントへ修正を依頼します。

## issue に対して QA を実行する

Copilot CLI は会話の開始時にプロジェクトのエージェントを読み込みます。プロファイルを作成した後、同じフィルターの会話を再開し、QA を選択すると、issue と計画の内容を引き継いで確認できます。

1. 次のコマンドを使ってエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> 作成したばかりのエージェントは、利用可能なエージェントの一覧にまだ表示されない場合があります。次のコマンドで有効化できます。

2. 次のプロンプトで、QA エージェントに機能をレビューするよう依頼します。

   ```plaintext
   issue と計画で決めた内容に照らしてフィルター機能をレビューしてください。PR を作成できる状態ですか？
   ```

3. QA エージェントが作業を開始します。
4. 完了したら、レポートを最後まで確認します。
