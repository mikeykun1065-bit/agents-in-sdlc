GitHub Pages にデプロイして、Space Quiz を誰でも利用できるようにしましょう。Copilot はワークフローの準備とデプロイを支援しますが、変更をレビューし、サイトが公開されたことを確認するのはあなたの役割です。

このレッスンでは、次のことを行います。

- Copilot に GitHub Pages のデプロイを設定するよう依頼します。
- マージする前にワークフローとプルリクエストをレビューします。
- デプロイの進行を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、まだ簡単に試せる場所がありません。単一ファイルのサイトを GitHub Pages で公開すれば、サーバーやランタイム依存関係を追加せずに公開 URL から利用できます。

## Copilot にデプロイの準備を依頼する

> [!WARNING]
> プルリクエストの作成によってコードがコミットおよびプッシュされることがあります。プロンプトを送る前に、承認設定と対象リポジトリを確認してください。**すべて承認**に設定されている場合、別途確認を求められないことがあります。

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリで GitHub Pages にデプロイできるよう準備してください。必要であれば Web サイトをビルドし、既定のブランチに変更が反映された後に GitHub Pages へデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリの説明とローカルでの実行方法を記載した README を追加してください。これらの変更を含むプルリクエストを作成し、そのリンクと必要な Pages の設定または権限を報告してください。マージ、自動マージの有効化、Pages 設定の変更、デプロイは行わないでください。レビューを待って停止してください。
```

## ワークフローとプルリクエストをレビューする

1. README がまだない場合に限り追加されていることを確認します。
2. ワークフローのビルドとデプロイの手順、トリガー、権限など、プルリクエストの変更をレビューします。
3. ワークフローが未マージのプルリクエストではなく、既定のブランチからデプロイすることを確認します。
4. 修正を依頼し、更新された差分をレビューします。マージを承認する前に、必要なプルリクエストのチェックがすべて成功するまで待ちます。

## マージとデプロイを承認する

> [!WARNING]
> 次のプロンプトを送信すると、レビュー済みプルリクエストのマージ、リポジトリの Pages 設定の変更、サイトの公開をエージェントに許可します。レビューを完了し、リポジトリとプルリクエストを確認してから送信してください。承認設定によっては、これらの操作に別途確認が求められない場合があります。

`<PR_NUMBER>` をレビューしたプルリクエストの番号に置き換え、次のプロンプトを別途送信します。

```plaintext
このリポジトリのプルリクエスト <PR_NUMBER> をレビューし、マージとデプロイを承認しました。GitHub Actions を使うよう GitHub Pages を有効にし、必要なチェックが成功した後にそのプルリクエストだけをマージして、デプロイが成功するまで監視してください。公開された Web サイトの最終 URL を報告してください。Pages の有効化またはマージの権限がない場合は、私が承認または実行する必要がある操作を正確に説明してください。サイトが公開されるまでは成功したと報告しないでください。
```

## デプロイを確認する

1. GitHub Actions のデプロイ実行が成功するまで確認します。
2. 報告された URL を開き、Space Quiz が読み込まれることを確認します。

エージェントに Pages の有効化やプルリクエストのマージを許可できない場合は、提示された具体的な手順に従ってください。デプロイが成功し、公開サイトが読み込まれるまでは完了とみなさないでください。
